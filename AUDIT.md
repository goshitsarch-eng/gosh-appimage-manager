still specifies "C++20, Qt 6, KDE Frameworks 6, Kirigami, CMake/ECM",
`org.kde.Platform//6.10`, and version `0.1.0` (lines 10-13). The tree contains
no Qt/CMake/QML. `docs/rewrite-3.0.0.md` and `docs/verification.md` record the
pivot to Rust + libcosmic. The brief is a stale requirements document; it is
still the most complete statement of the feature contract, so this audit treats
its *behavioural* requirements as binding and its *stack* claims as superseded.

Notes on the baseline:
* The clippy failure is a **pre-existing** baseline deviation, not caused by this
  audit. `docs/verification.md:44-48` claims clippy is clean; it is clean on the
  older toolchain that record was made with, but fails on the toolchain here
  (rustc/clippy 1.94.1). Recorded as **L-1**.
* `cargo build --offline` fails: the `[patch]` for `cosmic-text` cannot resolve
  without the crates.io index. Network builds work. Recorded as **L-2**.
* `--features gui` was **not** built: libcosmic v0.12 needs system Wayland/XKB
  development files that are absent in this container. All GUI findings below are
  from reading `src/gui.rs`; none required compilation to establish.
* `desktop-file-validate` and `appstreamcli` are not installed here, so the
  `just validate` gate could not be re-run.

## Phase 4 — GUI and platform conformance

### Applicable standard

The toolkit is **libcosmic** (`Cargo.toml:24,39`), System76's iced-based COSMIC
Epoch toolkit. The governing guidance is therefore, in order: **libcosmic's own
component guidance** (`widget::settings::section`, `nav_bar`, `widget::dialog`,
the `button::{standard,suggested,destructive}` variants), the **freedesktop
Desktop Entry / Icon Theme / AppStream specifications** for platform
integration, and **WAI-ARIA APG patterns** as the vendor-neutral reference for
the interaction semantics libcosmic does not itself specify (focus order, modal
dialog behaviour, accessible naming). Apple HIG, Material and Fluent do not
apply. README:2 and `metainfo.xml` also claim Plasma-native behaviour; the
COSMIC toolkit does not provide Plasma integration, so that claim is assessed
against freedesktop specs only.

## Phase 2 — Performance notes on what was measured vs. asserted

**Measured:**
* `glob_match` blow-up (**S-4**) — release build, timed over six pattern lengths:
  0.125 ms / 0.77 ms / 6.7 ms / 57 ms / 507 ms / 3.15 s for pattern lengths
  5/7/9/11/13/15 against a 50-character asset name. Clean ~8× per two added
  characters; the fit implies ≈9 hours at a 25-character pattern.
* Baseline build 1m17s; full test suite 79 tests in well under a second
  (all seams are fakes, so the suite exercises no real I/O timing).

**Asserted from code, not measured** (no display server for GUI timing, and no
large real AppImage corpus in this container): **P-1** through **P-9**. Each
names the exact call site and the work performed there; none required
measurement to establish that the work happens on the wrong thread or repeats.

**Not applicable:** there is no ORM, no query builder, and no user-facing SQL —
the registry is loaded wholesale into `Vec<InstalledApp>` and queried in memory.
So the classic N+1/`SELECT *`/missing-index findings do not arise; the analogous
problem here is **P-4** (full-table rewrite per mutation) and **P-5** (syscalls
per in-memory lookup). Pagination is likewise not applicable at the expected
scale (tens of apps), and its absence is not counted as a finding.

## Scope limits

- **No rendered frame.** The GUI compiles and type-checks (`cargo check
  --features gui` and `clippy --features gui --all-targets -- -D warnings`
  both pass after installing `libwayland-dev` and `libxkbcommon-dev`), and
  every operation behind it is covered by tests. No screenshot was taken and
  no frame was drawn: this container has no compositor, and X11 is broken
  upstream (G-9). Contrast ratios, focus rings and text scaling therefore
  remain unverified rather than passed.
- **No Flatpak build.** `flatpak-builder` is not installed here, so neither
  architecture was rebuilt and the packaged probes were not re-run.
- **No AppStream/desktop validation.** `desktop-file-validate` and
  `appstreamcli` are absent. `data/com.goshapps.AppImageManager.desktop`
  changed (`%U` → `%F`) and should be re-validated where those tools exist.
