# QA audit, 2026-10-08

This record covers a hands-on audit of Gosh AppImage Manager 3.0.0 (Rust core,
Flutter GUI), run on aarch64 with the freedesktop 26.08 Flatpak. It lists what
was tested, what was found, what was fixed, what is still open, and how each
result was checked. The verification record for the gates and the packaged
build is `docs/verification.md`, section 9.

## Application tested

- Version 3.0.0. Branch `feature/flutter-bridge-spike`, with uncommitted changes
  on top of commit `ca03750`. The final tree is round 7.
- Flatpak bundle built from that tree with `just flatpak-aarch64` on the
  freedesktop 26.08 runtime.

## Test environment

- Fedora Asahi, aarch64, kernel 7.1 (16k pages).
- Wayland session with XWayland (`DISPLAY=:0`), GNOME Shell (Mutter) as the
  window manager. The window runs at scale 2 under XWayland.
- Flutter 3.47.6, Rust 1.99.0, just 1.58.0, flutter_rust_bridge 2.13.0.
- squashfs-tools 4.6.1 (`unsquashfs`) on the host and in the Flatpak.
- Fixtures were built with `mksquashfs`. Some are AppImage layouts, with an ELF
  header and the squashfs payload at its offset. None is a third-party AppImage,
  except one read-only probe of a real type-2 AppImage made earlier.

## Method and limits

- OS-level pointer and key input does not reach the Flutter window on this host
  (XTEST is unavailable). In-app interaction ran through the Flutter integration
  binding, in the real app process, with the real Rust core and a real window.
- Window resizing and maximize ran through X11 (ctypes). Screenshots came from
  the real window (`import`) and from widget surfaces.
- Every run used scratch homes, `GOSHAIM_HOME` and XDG directories. The real
  home was compared before and after each pass. Packaged runs used a scratch
  `HOME` too.
- The native file chooser, the Trash on the host, and the desktop's own
  `xdg-open` were replaced by seams in the walkthrough, so their behaviour is not
  observed end to end.

## Areas tested

- **Walkthrough (in-app):** a 128-item inventory (INV-001 to INV-128) of every
  page, dialog, menu, control, text field, shortcut, empty and error state. Each
  item has a check, and the restart checks reopen the same home.
- **Layout:** widget surfaces at 360×480, 420×1400, 800×600, 1280×800,
  2400×420 and 2560×1440. Window sizes from 200×200 to 2560×1440 at scale 2.
- **Window and persistence (real window and CLI):** startup, min size,
  maximize and restore, minimize, a 20-resize burst, settings persistence on
  startup and restart (P0 to P7), corrupt and unreadable settings, and logs.
- **CLI:** metadata, integrate, the unsafe fallback with and without confirmation,
  the probe, the GitHub update source, and the refusal paths.
- **Packaged:** version, self-test, a real-layout metadata read, and an isolated
  GUI launch in the Flatpak.

## Remaining issues

- **Targeted walkthrough re-checks** on the final tree. Round 7 passed 9 of 9:
  cancel from Tasks and from the status bar, the Detail buttons and the library
  version at 800×600, and the GitHub command text. Round 8 passed 11 of 11,
  including the status-bar cancel aftermath (QA3-009), which no longer reproduces.
- **Decision: `wait-timeout`.** The crash fix removed the `wait-timeout` crate
  from `Cargo.toml`, `Cargo.lock` and the Flatpak source list. It was outside the
  list the owner had approved. The owner can keep the removal, or restore the
  dependency and carry a patch.
- **D-19 and QA2-006, restore after maximize:** the window manager sets the size.
  Not fixed by the app.
- **GitHub sources that need `filename`:** the GUI shows the CLI command. The
  owner decided to keep one key=value field.
- **The unsafe fallback** runs a real AppImage only when the stored setting is on
  and the file is confirmed. It is tested with stand-in programs and a read-only
  probe. It has not been run end to end on a real third-party AppImage in tests.
- **x86_64 bundle and Flatpak:** not built or checked for this tree, because
  this host is aarch64. The CI runs for this branch, including the new
  `squashfs-tools` install before `cargo test`, had not been checked when this
  record was written.
- **Live input:** pointer and keyboard input from the OS, drag, edge resize,
  screen readers. Not testable on this host.
- **Walkthrough harness:** the overflow check cannot see framework errors inside
  `testWidgets`, so overflow evidence comes from the banner scan. The harness
  sizes were corrected in the final run, but its cascades were not all removed.
- **Known product limit:** DwarFS AppImages are detected but their metadata is
  not read (see the README).
- **Operational note:** a leftover sandboxed GUI from a packaged launch check
  survived the smoke script. The script was corrected, and nothing from the QA
  runs remains running.

## Verification

- Gate on the round 8 tree (`docs/verification.md`, section 9): root 275 tests,
  bridge 20, Flutter 360, the release build, the arm64 bundle, and the GUI smoke
  test, all passing.
- Flatpak 26.08, aarch64, round 7: build exit 0. Packaged version 3.0.0, the
  self-test passes, the real-layout metadata reads "Alpha Notes" through
  `unsquashfs`, and the isolated GUI launch shows its window, stays up and stops
  cleanly.
- The real home was compared before and after each pass. One packaged check (an
  early round, without a scratch home) wrote an empty registry into the real home
  at 11:49. That was a mistake in the check, not an app defect; the registry held no
  app data, and the owner removed it. Later packaged checks used scratch homes, and
  the real home stayed unchanged. The two Trash items were moved by the owner.
